# FUME Client Intelligence Platform – Prototype Documentation

Welcome to the FUME Client Intelligence Platform. This prototype is designed to help wellness coaches analyze multi-day client conversations, extract key performance metrics, and flag high-risk situations while maintaining high truth-grounding and human review.

---

## 🚀 What We Built
We built an interactive, glassmorphic Single Page Application (SPA) Dashboard that functions as a Coach's Co-pilot. It includes:
1. **Interactive Dual-Panel Interface**:
   - **Left Panel (Transcript Explorer)**: A clean chat bubble layout of the 8-day conversation, color-coded by speaker (Client vs. Coach).
   - **Right Panel (Intelligence Hub)**: Organized tabbed views for different client dimensions:
     - *Overview*: Highlights the Weekly Client Summary, Risk/Attention flags (flashing crimson indicators for urgent flags), and Recommended Coach Actions.
     - *Trackers*: Dynamic interactive SVG charts for sleep, steps, and water intake.
     - *Taxonomy*: A dedicated table that segregates data points into FUME's requested truth categories: Confirmed Facts, Client-Reported, AI-Inference, and Missing Information.
     - *Barriers & Actions*: Focuses on client bottlenecks and pending tasks.
     - *Review & Edit*: Allows coaches to edit findings inline, approve/reject reports, and export approved records to a schema-compliant JSON payload.
2. **Bidirectional Evidence Grounding**:
   - Hovering over or clicking any finding in the taxonomy highlights and automatically scrolls to the exact day/message in the transcript that supports it.
3. **JSON Export Utility**:
   - A single-click utility that validates the current state against the platform's JSON schema and downloads it as a `.json` file for backend ingestion.

---

## 🔑 Key Assumptions
- **Coach-in-the-Loop Model**: Wellness recommendations are high-stakes. The AI should generate *drafts* of summaries, metrics, and actions, but a professional coach must explicitly review and edit/approve the output before it is finalized.
- **Strict Metric Extraction**: If the client mentions a metric qualitatively (e.g., "water done") without a quantity, the system treats it as `null` (missing) on charts and reports it as "Missing Information" to avoid metric fabrication.
- **Scope of Inferences**: AI-generated inferences are strictly behavioral and environmental (e.g., "Work pressure correlates with sleep drops"). The system is explicitly blocked from making medical diagnoses (e.g., Gastritis or Insomnia).

---

## ⚠️ What Could Go Wrong (Failure Risks)
1. **Context/Temporal Drift**: In longer multi-week conversations, the LLM might associate a symptom from week 1 with a meal from week 3, leading to false causal inferences.
2. **Qualitative Misinterpretation**: If a client writes sarcasm or uses idiomatic expressions (e.g., "Slept like a rock but still feel dead"), the AI might report "Excellent sleep quality" based only on "slept like a rock."
3. **Voice-to-Text Transcription Noise**: If the raw transcript is generated by voice-to-text, typos (e.g., "ate chana" transcribed as "hate chana") will lead to faulty nutritional compliance reporting.

## 📈 What We Would Improve Next
1. **Automated Vector-Based Grounding Validator**:
   - Implement an automated checking step that calculates the semantic similarity between the extracted finding and the cited text quote. If the similarity score is below a certain threshold (e.g., cosine similarity < 0.7), the finding is highlighted in yellow as "Low Confidence" for the coach.
2. **Real-time LLM Backend Integration**:
   - Set up a lightweight FastAPI backend utilizing Gemini 2.5 Flash's structured JSON output mode to enable uploading *any* text file and generating the dashboard dynamically.
3. **Cross-Client Risk Alerting**:
   - Build a supervisor view that aggregates risk flags across all of a coach's clients (e.g., highlighting any client who has had less than 6 hours of sleep for 3 consecutive days or who reported extreme work stress).
